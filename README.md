# 社区矛盾纠纷调解平台

面向社区网格员、调解员、当事人和街道司法所的全流程矛盾调解管理系统。

## 原始需求

> 搭建一个给社区网格员、调解员、当事人和街道司法所使用的矛盾调解平台，Vue3 页面展示案件池、调解进度、协议履行和回访提醒，NestJS 保存纠纷材料、会议记录、协议条款和督办结果。网格员登记邻里噪声、停车占位、物业收费、家庭赡养等纠纷线索；调解员安排调解时间、参会人员、诉求和证据材料；当事人确认协议条款、履行节点和补充说明；司法所查看重大纠纷、超期案件和回访结果。系统要把线索受理、分派调解、会议记录、协议签署、履行跟踪、回访督办连成闭环。拒绝参会、协议逾期、重复投诉、情绪升级要分别影响案件状态。
> 增加多方参会协调。纠纷涉及物业、业委会或亲属时，调解员可以追加参会方；系统记录每方诉求、是否到场和缺席原因，关键方缺席时会议不能直接生成最终协议。
> 加入协议履行节点。调解协议可以拆成多个履行事项，例如挪车、补缴费用、维修漏水和道歉；每个节点有责任人、期限和证据照片，逾期后进入督办。
> 支持情绪升级预警。网格员回访中记录威胁、聚集、持续辱骂等情况后，案件进入重点关注；司法所可以要求增加联席调解或转入法律援助。
> 增加重复投诉合并。同一当事人围绕同一事项反复投诉时，系统提示历史案件、协议履行情况和回访记录；调解员可以合并处理，但不能删除原投诉轨迹。
> 请实现回访督办与案件闭环管理。司法所可查看超期案件（从线索登记起超过30天未结案）和重大纠纷（涉多人、涉金额超阈值、涉信访风险）。调解员结案后需发起回访，回访结果分为"已履行""部分履行""未履行"。未履行的案件自动生成督办单，指派原调解员跟进。重复投诉的案件（同一当事人对同一事由再次登记线索）需关联原案件，并在原案件时间轴中标记为"复发"，案件状态回退到"待调解"。演示时需验证超期案件列表展示、回访未履行生成督办、重复投诉关联原案件的完整闭环。

## 项目简介

### 核心业务闭环

```
线索受理 → 分派调解 → 会议记录 → 协议签署 → 履行跟踪 → 回访督办
     ↓          ↓          ↓          ↓          ↓          ↓
  网格员      调解员      调解员      当事人    各方协作    网格员/司法所
```

### 四种角色

| 角色 | 账号 | 权限范围 |
|------|------|----------|
| 社区网格员 | 张网格员 | 线索登记、走访记录、回访执行 |
| 调解员 | 李调解员 | 案件分派、会议安排、协议草拟 |
| 当事人 | 王当事人 | 查看进度、确认协议、履行节点 |
| 街道司法所 | 赵司法所 | 全量案件、重大督办、超期监控 |

> 登录页可直接选择角色体验，无需密码

### 状态影响规则

| 事件 | 触发影响 |
|------|----------|
| 当事人拒绝参会 | 状态 `meeting_refused`，拒会计数 +1，≥2 次情绪升级 |
| 协议履行逾期 | 状态 `fulfillment_overdue`，逾期计数 +1，标记逾期 |
| 重复投诉 | 状态 `repeat_complaint`，重复计数 +1，情绪升级 |
| 情绪升级 | 状态 `escalated`，标记重大纠纷，情绪等级 = 5 |
| 回访发现威胁/聚集 | 自动创建情绪预警，案件标记重点关注，威胁/聚集类直接触发情绪升级 |
| 回访发现持续辱骂 | 自动创建情绪预警，案件标记重点关注，情绪等级提升 |
| 案件合并 | 被合并案件状态变为 `merged`，主案件重复计数 +1，情绪等级提升，保留原投诉轨迹 |
| 回访结果"已履行" | 案件状态更新为 `case_closed`（已结案） |
| 回访结果"部分履行" | 案件标记为重点关注，持续跟踪履行情况 |
| 回访结果"未履行" | 案件状态更新为 `supervision_pending`（督办中），自动生成督办单，指派原调解员，限期 7 天跟进 |
| 重复投诉关联原案件 | 新案件标记 `isRelapse=true`，状态回退为 `assigned`（待调解），复发次数 +1，原案件时间轴添加"复发"标记，自动生成复发督办单 |
| 超期 30 天未结案 | 自动计入超期案件列表，司法所督办视图可见，`daysOverdue` 自动计算超期天数 |
| 重大纠纷判定 | 涉多人（≥5 人）、涉金额（≥5 万元）、涉信访风险，任一条件满足即标记 `isMajor=true` |

### 情绪升级预警机制

- **预警类型**：威胁言论、聚集倾向、持续辱骂、其他异常
- **触发方式**：网格员回访时手动标记，系统自动创建预警记录
- **升级处置**：司法所可选择联席调解、法律援助、重点关注三种处置方式
- **重点关注**：标记后案件在督办列表中高亮显示

### 重复投诉合并机制

- **相似检测**：基于当事人姓名 + 纠纷类别自动匹配历史案件
- **登记提示**：线索登记时自动提示同当事人历史案件
- **合并处理**：调解员可将多个案件合并，保留全部投诉轨迹
- **合并影响**：主案件重复计数递增，情绪等级提升，≥2 次自动标记重大纠纷

## 技术栈

### 前端
- Vue 3 + TypeScript + Composition API
- Vite 5 构建工具
- Vue Router 4 路由（12个页面）
- Pinia 状态管理
- TailwindCSS 3 样式系统
- Lucide Vue Next 图标
- dayjs 时间处理
- Axios + Mock 双模式（后端不可用时自动降级）

### 后端
- NestJS 10 + TypeScript
- 模块化架构（Cases / Clues / Meetings / Agreements / Followups / Stats）
- 内存存储 InMemoryStore（启动即用，无需数据库）
- dayjs 时间处理
- CORS 全局开启

### 部署
- Docker Compose 一键编排
- Nginx 承载前端 + 反向代理后端 API

## 启动方式

### 前置要求

- Node.js ≥ 18
- Docker ≥ 20.10
- Docker Compose ≥ 2.0
- pnpm 或 npm（推荐 pnpm）

### 方式一：Docker 一键启动（推荐）

#### 1. 构建并启动（前台）

```bash
docker compose up --build
```

#### 2. 构建并启动（后台）

```bash
docker compose up --build -d
```

启动后访问：
- 前端页面：http://localhost:8080
- 后端 API：http://localhost:3000/api/cases

#### 3. 查看日志

```bash
docker compose logs -f
```

#### 4. 停止并清理

```bash
docker compose down
```

### 方式二：本地开发启动

#### 1. 安装依赖

后端：
```bash
cd backend
npm install
```

前端：
```bash
cd frontend
npm install
```

#### 2. 启动后端（端口 3000）

```bash
cd backend
npm run start:dev
```

后端启动验证：
```bash
curl http://localhost:3000/api/cases
```

#### 3. 启动前端（端口 5173）

另开终端：
```bash
cd frontend
npm run dev
```

访问地址：http://localhost:5173

> 前端已配置 `/api` 代理到 `http://localhost:3000`

### 方式三：仅前端 Mock 模式（无需后端）

```bash
cd frontend
npm install
npm run dev
```

访问 http://localhost:5173，所有 API 请求自动使用内置 Mock 数据，可独立体验完整功能。

## API 接口概览

| 模块 | 路由前缀 | 主要接口 |
|------|----------|----------|
| 案件 | `/api/cases` | `GET /` 列表 `GET /stats` 统计 `GET /supervision` 督办 `PUT /:id/status` 更新状态 `GET /similar` 相似案件查询 `GET /:id/warnings` 预警记录 `POST /:id/warnings` 添加预警 `POST /:id/escalation-action` 升级处置 `GET /:id/merge-records` 合并记录 `POST /:id/merge` 合并案件 `GET /:id/merged-info` 合并详情 `GET /overdue` 超期案件列表 `GET /major` 重大纠纷列表 `GET /supervision-orders` 督办单列表 `GET /supervision-orders/:id` 督办单详情 `PUT /supervision-orders/:id` 更新督办单 `GET /:id/supervision-orders` 案件督办单 `POST /check-relapse` 检测重复投诉 `POST /create-with-relapse` 创建复发关联案件 |
| 线索 | `/api/clues` | `POST /` 登记 `PUT /:id/accept` 受理 `PUT /:id/reject` 驳回 `POST /check-repeat` 检测重复投诉 |
| 会议 | `/api/meetings` | `POST /` 创建 `PUT /:id/complete` 完成 `PUT /:id/refuse` 拒会记录 |
| 协议 | `/api/agreements` | `POST /` 草拟 `PUT /:id/sign` 签署 `PUT /:id/reject` 拒绝 |
| 履行 | `/api/agreements/:id/fulfillments` | `GET /` 节点列表 `PUT /nodes/:nodeId` 更新节点 |
| 回访 | `/api/followups` | `POST /` 创建 `PUT /:id/complete` 完成 `GET /upcoming` 待办 |
| 统计 | `/api/stats` | `GET /` 看板统计 |

## 页面列表（12 个）

1. **登录页** — 4 角色卡片式登录，体验不同视角
2. **首页看板** — 统计卡片 + 月度趋势 + 类别分布 + 待办
3. **案件池** — 双视图 + 多维筛选 + 风险标签组
4. **调解进度** — 6 阶段流水线可视化 + 风险筛选
5. **线索登记** — 完整表单 + 4 类纠纷快速模板
6. **线索列表** — 线索受理 / 驳回
7. **调解会议** — 会议 CRUD + 拒会记录触发状态升级
8. **协议签署** — 条款草拟 + 多方签名可视化 + 须知弹窗
9. **履行跟踪** — 环形进度 + 节点状态机 + 逾期侧栏
10. **回访督办** — 4 方式回访 + 5 星评分 + 履行状态选择（已履行/部分履行/未履行）+ 未履行自动生成督办单
11. **司法所督办** — 4 标签页（重点督办/超期案件/重大纠纷/督办单）+ 超期 30 天自动统计 + 督办单 CRUD + 复发标记
12. **案件详情** — 全景视图：当事人 + 协议 + 会议 + 风险评估 + 流转时间线 + 复发标记 + 关联原案件 + 督办记录

## 注意事项

1. **数据存储**：后端使用内存存储，进程重启数据会丢失，适合演示使用；如需持久化请替换为 PostgreSQL / MySQL
2. **权限演示**：角色切换位于顶栏右上角，无需登录凭据，适合演示四种视角
3. **API 降级**：前端后端不可用时自动切到 Mock，不会白屏
4. **Docker 验证**：首次构建时 npm ci 较慢属正常，后续构建有缓存
5. **端口占用**：若 8080 或 3000 被占用，请修改 `docker-compose.yml` 的 ports 映射
